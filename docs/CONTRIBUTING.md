# Documentation guidelines

Write user-facing pages in English. Organize documentation by task or subsystem;
keep related API methods on one page rather than creating a page per function.
Use getting-started, concepts, api, guides, devices and examples directories.
Link new pages from their section index and keep figures under assets.

Explain units, sign conventions, data freshness and missing capabilities. Separate
current behavior from proposed conventions. Keep test logs and asset-production
details out of user guides. Validate claims against public APIs and their implementation.

Use real model-specific oblique product views for axis diagrams. Preserve aspect
ratio. X is red, Y green, Z blue; add axis names and positive signs so color is
not the only identifier. Identify the housing front and top. State the viewing
direction for rotation arrows and use the right-hand rule.

Record unavailable imagery or uncertain mappings as pending; do not substitute
another model’s picture or mark untested devices as verified. Check rendered
figures, local links, declarations and representative example compilation.
